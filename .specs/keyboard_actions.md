# Spec: Keyboard Actions

All keyboard-triggered actions in the dashboard.

Implementation: `app/event/`, `app/ui/*/screen.py`.

---

## Action table

Actions marked **Global** are active on every screen. Actions marked with a screen name are only active on that screen. Actions marked **pending** have complete implementations but are not yet wired in the current build.

| Action | Key | Scope | Trigger type | Hold duration | Sound | Effect | Status |
|---|---|---|---|---|---|---|---|
| Event marker | `Return` / `Enter` | Global | Instant (press) | — | `alarm.wav` (one-shot) | Marks next CSV row with `"MARK"` | **pending** |
| Lambda loop toggle | `Space` | Global | Hold | 2000 ms | `alarm.wav` (one-shot) | Sends `LAMBDA_LOOP_OPEN` or `LAMBDA_LOOP_CLOSE` to ECU | **pending** |
| Return to home | `ESC` | Global | Instant (press) | — | — | Navigates to HomeScreen | Active |
| Home menu navigate | `↑` / `↓` | HomeScreen | Instant (press) | — | — | Moves menu selection up/down | Active |
| Home menu confirm | `Enter` | HomeScreen | Instant (press) | — | — | Opens selected screen | Active |
| VE increase | `↑` | VE Calibration | Instant (press) | — | — | `adjust_ve(rpm, map, +6.0)` | Active |
| VE decrease | `↓` | VE Calibration | Instant (press) | — | — | `adjust_ve(rpm, map, -6.0)` | Active |
| VE reset | `R` | VE Calibration | Instant (press) | — | — | Restores all VE cells to original values | Active |

## Trigger types

### Instant

Fires on key press. Implementation: `QObject` connected to `AppWindow.key_event(int)` (global) or `app_window.key_event` filtered inside a specific screen's `handle_key(int)` slot.

### Hold

Fires after the key is held continuously for the configured duration. Implementation: `KeyHoldDetector`.

**Rules:**
- Timer starts on the first key press event.
- Timer is cancelled on key release.
- Auto-repeat key events (generated by the OS when a key is held) do not restart the timer — only a fresh press after a release does.
- `triggered` signal is emitted exactly once per successful hold.

## Action: Event Marker

**Class:** `EventMarker` (`app/event/marker.py`)

**Trigger keys:** `Qt.Key.Key_Return`, `Qt.Key.Key_Enter`

**Behavior:**
1. On matching key press: play `alarm.wav` from the start (stop if already playing, then play).
2. Emit `event_triggered` signal.
3. `LogWriter` receives `event_triggered` and sets a flag; the next CSV row will include `"MARK"` in the `Event` column.

---

## Action: Lambda Loop Toggle

**Classes:** `KeyHoldDetector` (detector) + `LambdaToggle` (action) (`app/event/`)

**Trigger:** `Space` held for 2000 ms

**Behavior:**
1. `KeyHoldDetector.triggered` fires after 2 s hold.
2. `LambdaToggle.handle_trigger()` is called.
3. Play `alarm.wav` from the start.
4. Read `vehicle_state.is_lambda_loop_closed()`:
   - If closed → emit `command_requested(EcuCommand.LAMBDA_LOOP_OPEN)`
   - If open → emit `command_requested(EcuCommand.LAMBDA_LOOP_CLOSE)`
5. `EcuConnection.send_command()` receives the command and queues it.
6. `LambdaLoopStateProcessor.on_command_sent()` receives the same command and updates `VehicleState` immediately (without waiting for the ECU to confirm).

**Intent:** the immediate state update in step 6 ensures the UI reflects the toggle instantly, because the ECU's confirmation may arrive several frames later.

## Adding a new action

### Instant action

1. Add a row to the action table above.
2. Create a `QObject` subclass in `app/event/`.
3. Connect `Dashboard.key_event` to a slot that filters by `key == int(Qt.Key.Key_XYZ)`.
4. Wire in `main.py`.

### Hold action

1. Add a row to the action table above.
2. Create a `KeyHoldDetector(key=Qt.Key.Key_XYZ, hold_ms=N)`.
3. Connect `AppWindow.key_event` → `on_key_pressed` and `AppWindow.key_released` → `on_key_released`.
4. Connect `triggered` to the action handler.
5. Wire in `main.py`.

**Note:** `KeyHoldDetector` stores the key as `int(key)` internally to ensure correct comparison with the `int` values emitted by `AppWindow.key_event`.
