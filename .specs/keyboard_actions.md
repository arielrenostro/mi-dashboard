# Spec: Keyboard Actions

All keyboard-triggered actions in the dashboard.

Implementation: `app/event/`, `app/ui/*/screen.py`.

---

## Action table

Actions marked **Global** are active on every screen. Actions marked with a screen name are only active on that screen.

| Action | Key | Scope | Trigger type | Hold duration | Sound | Effect | Status |
|---|---|---|---|---|---|---|---|
| Event marker | `Return` / `Enter` | Global | Instant (press) | — | `alarm.wav` (one-shot) | Marks next CSV row with `"MARK"` | Active |
| Lambda loop toggle | `Space` | Global | Hold | 2000 ms | `ve_sound` (one-shot) | Sends `LAMBDA_LOOP_OPEN` or `LAMBDA_LOOP_CLOSE` to ECU | Active |
| Return to home | `ESC` | Global | Instant (press) | — | — | Navigates to HomeScreen | Active |
| Home menu navigate | `↑` / `↓` | HomeScreen | Instant (press) | — | — | Moves menu selection up/down | Active |
| Home menu confirm | `Enter` | HomeScreen | Instant (press) | — | — | Opens selected screen | Active |
| VE increase | `↑` | VE Calibration | Instant (press) | — | `ve_sound` | `adjust_ve(rpm, map, +5.0)` + 1 s debounce to ECU | Active |
| VE decrease | `↓` | VE Calibration | Instant (press) | — | `ve_sound` | `adjust_ve(rpm, map, -5.0)` + 1 s debounce to ECU | Active |
| VE % increment | `G` | VE Calibration | Instant (press) | — | — | Opens `PercentageDialog`; on confirm calls `adjust_ve_by_percentage(rpm, map, pct)` + 1 s debounce to ECU | Active |
| VE reset | `R` | VE Calibration | Instant (press) | — | `ve_sound` | Restores all VE cells to original values + sends to ECU | Active |
| Lambda open | `O` | VE Calibration | Instant (press) | — | `open_sound` | Sends `LAMBDA_LOOP_OPEN` to ECU | Active |
| Lambda close | `P` | VE Calibration | Instant (press) | — | `closed_sound` | Sends `LAMBDA_LOOP_CLOSE` to ECU | Active |

## Trigger types

### Instant

Fires on key press. Per-screen: handled inside `keyPressEvent` in the `Screen` subclass. Global: connected via `AppWindow.key_event(int)` in `main.py`.

### Hold

Fires after the key is held continuously for the configured duration. Implementation: `KeyHoldDetector`.

**Rules:**
- Timer starts on the first key press event.
- Timer is cancelled on key release.
- Auto-repeat key events (generated by the OS when a key is held) do not restart the timer — only a fresh press after a release does.
- `triggered` signal is emitted exactly once per successful hold.

## Action: Event Marker

**Class:** `EventMarker` (`app/event/marker.py`)

**Trigger keys:** `Qt.Key.Key_Return`, `Qt.Key.Key_Enter`

**Behavior:**
1. On matching key press: play `alarm.wav` from the start.
2. Publish `EventMarkRequestedEvent` to the event bus.
3. `LogWriter` is subscribed in `main.py` via `event_bus.subscribe(EVENT_MARK_REQUESTED, log_writer.set_event_pending)`.

**Wiring in `main.py`:**
```python
event_marker = EventMarker(config.alarm.sound)
app_window.key_event.connect(event_marker.handle_key)
event_bus.subscribe(AppEventType.EVENT_MARK_REQUESTED,
                    lambda _: log_writer.set_event_pending())
```

## Action: Lambda Loop Toggle

**Classes:** `KeyHoldDetector` (detector) + `LambdaToggle` (action) (`app/event/`)

**Trigger:** `Space` held for 2000 ms

**Behavior:**
1. `KeyHoldDetector.triggered` fires after 2 s hold.
2. `LambdaToggle.handle_trigger()` is called.
3. Play `ve_sound` from the start.
4. Read `vehicle_state.is_lambda_loop_closed()`:
   - If closed → publish `EcuCommandRequestedEvent(EcuCommand.LAMBDA_LOOP_OPEN)`
   - If open → publish `EcuCommandRequestedEvent(EcuCommand.LAMBDA_LOOP_CLOSE)`
5. `EcuConnection.send_command()` is subscribed to `ECU_COMMAND_REQUESTED` in `main.py`.

**Wiring in `main.py`:**
```python
lambda_toggle = LambdaToggle(config.ve_calibration.ve_sound)
space_detector = KeyHoldDetector(Qt.Key.Key_Space, 2000)
space_detector.triggered.connect(lambda_toggle.handle_trigger)
app_window.key_event.connect(space_detector.on_key_pressed)
app_window.key_released.connect(space_detector.on_key_released)
event_bus.subscribe(AppEventType.ECU_COMMAND_REQUESTED,
                    lambda e: get_ecu_connection().send_command(e.command, e.args))
```

## Adding a new action

### Instant action (screen-local)

1. Add a row to the action table above.
2. Override `keyPressEvent` in the target `Screen` subclass and filter by key.

### Instant action (global, event-driven)

1. Add a row to the action table above.
2. Create a `QObject` subclass in `app/event/` that publishes an `AppEvent` to the bus.
3. Connect `app_window.key_event` to its `handle_key(int)` slot in `main.py`.
4. Subscribe the consumer to the bus event in `main.py`.

### Hold action

1. Add a row to the action table above.
2. Create a `KeyHoldDetector(key=Qt.Key.Key_XYZ, hold_ms=N)`.
3. In `main.py`: connect `app_window.key_event` → `on_key_pressed` and `app_window.key_released` → `on_key_released`.
4. Connect `triggered` to the action handler.

**Note:** `KeyHoldDetector` stores the key as `int(key)` internally to ensure correct comparison with the `int` values emitted by `AppWindow.key_event`.
