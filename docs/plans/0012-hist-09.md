# HIST-09: Refatorar AlarmProcessor e LambdaLoopStateProcessor para Usar o Bus

## Contexto

`AlarmProcessor` é um `QThread` com loop de 100ms para controle de áudio — desnecessário dado que o controle pode ser reativo. `LambdaLoopStateProcessor` é conectado via `StateProcessorRegister` ao `signal_processor.emitter` (dict legacy) e ao `ecu_connection.emitter` (string raw), ambas conexões fora do Bus. Ambos precisam migrar para o Bus.

## História de Usuário

Como desenvolvedor, quero que o `AlarmProcessor` deixe de usar `QThread` e passe a controlar o áudio reativamente, e que o `LambdaLoopStateProcessor` ouça eventos do Bus em vez de sinais diretos, para simplificar a arquitetura e eliminar conexões fora do Bus.

## Requisitos Funcionais

### AlarmProcessor

- RF01: Remover `QThread` de `AlarmProcessor` — não herdar mais de `QThread`.
- RF02: Manter `QObject` como base para que `QTimer` e `QMediaPlayer` funcionem na main thread.
- RF03: `AlarmProcessor` se inscreve em `AppEventType.SIGNALS_RECEIVED` no Bus (já faz isso — manter).
- RF04: Criar `QTimer` interno (`_audio_timer`) com intervalo de 100ms para verificar `vehicle_state.is_any_alarm_firing()` e controlar play/stop do áudio.
- RF05: `_audio_timer` inicia no `start()` e para no `stop()`.
- RF06: Como `AlarmProcessor` agora roda inteiramente na main thread, os sinais `_play_requested` e `_stop_requested` com `QueuedConnection` não são mais necessários — `player.play()` e `player.stop()` podem ser chamados diretamente.
- RF07: `_handle_status` (callback de fim de mídia) continua verificando `vehicle_state.is_any_alarm_firing()` para fazer loop — comportamento de re-play ao fim da mídia fica intacto.

### LambdaLoopStateProcessor

- RF08: `LambdaLoopStateProcessor` se inscreve em `AppEventType.SIGNALS_RECEIVED` no Bus para receber sinais.
- RF09: `LambdaLoopStateProcessor` se inscreve em `AppEventType.ECU_COMMAND_RESPONSE` no Bus para receber confirmações de lambda loop open/close.
- RF10: Remover `on_command_received(cmd, args)` como método chamado externamente; substituir por callback interno de `ECU_COMMAND_RESPONSE`.
- RF11: `StateProcessorRegister` deve ser eliminado ou simplificado ao ponto de não ter mais conexões diretas.

## Requisitos Não Funcionais

- RNF01: `AlarmProcessor` deve ser instanciável sem chamar `.start()` de QThread — a inicialização deve acontecer no construtor ou em um método `start()` simples que inicia o `_audio_timer`.
- RNF02: Thread safety: sem threads separadas, o `QTimer` roda na main thread. `vehicle_state.is_any_alarm_firing()` usa `RLock` internamente — chamada segura da main thread.
- RNF03: `LambdaLoopStateProcessor` não é mais um `Processor` com interface legada — pode ser simplificado para um `QObject` simples.

## Especificações Técnicas

### AlarmProcessor refatorado

```python
class AlarmProcessor(QObject):  # não mais QThread

    def __init__(self, sound: str):
        super().__init__()

        self.audio_output = QAudioOutput()
        self.audio_output.setVolume(1.0)
        self.player = QMediaPlayer()
        self.player.setAudioOutput(self.audio_output)
        self.player.setSource(QUrl.fromLocalFile(sound))
        self.player.mediaStatusChanged.connect(self._handle_status)

        self._is_playing = False
        self._alarm_until: Dict[Signal, float] = {}

        self._audio_timer = QTimer()
        self._audio_timer.setInterval(100)
        self._audio_timer.timeout.connect(self._check_audio_state)

        event_bus.subscribe(AppEventType.SIGNALS_RECEIVED, self._on_signals_received)

    def start(self):
        self._audio_timer.start()

    def stop(self):
        self._audio_timer.stop()
        self.player.stop()
        self._is_playing = False

    def _check_audio_state(self):
        should_play = vehicle_state.is_any_alarm_firing()
        if should_play and not self._is_playing:
            self.player.play()
            self._is_playing = True
        elif not should_play and self._is_playing:
            self.player.stop()
            self._is_playing = False

    def _handle_status(self, status):
        if status == QMediaPlayer.MediaStatus.EndOfMedia:
            if vehicle_state.is_any_alarm_firing():
                self.player.play()
            else:
                self._is_playing = False

    def _on_signals_received(self, event: SignalsReceivedEvent):
        self.process_signals(event.data)

    def process_signals(self, signals: Dict[Signal, ParsedSignal]):
        now = time.time()
        for signal, data in signals.items():
            alarm = signal.value["alarm"]
            duration = alarm.get("duration_s", 2.0)
            in_alarm = self._check_in_alarm(alarm, data)
            until = self._alarm_until.get(signal, 0.0)
            if in_alarm and now >= until:
                new_until = now + duration
                self._alarm_until[signal] = new_until
                vehicle_state.set_alarm(signal, True, until=new_until)  # HIST-07
                event_bus.publish(AlarmFiredEvent(signal=signal, until=new_until))
            elif not in_alarm:
                self._alarm_until.pop(signal, None)
                vehicle_state.set_alarm(signal, False)  # HIST-07

    @staticmethod
    def _check_in_alarm(alarm: dict, data: ParsedSignal) -> bool:
        ...  # sem mudança
```

### Remoção de StateProcessorRegister

`app/state/register.py` (se existir) conecta:
- `signal_processor.emitter → LambdaLoopStateProcessor.on_signal_received` → REMOVIDO (agora via Bus)
- `ecu_connection.emitter → LambdaLoopStateProcessor.on_command_received` → REMOVIDO (agora via ECU_COMMAND_RESPONSE)

O arquivo `register.py` pode ser apagado. A instanciação de `LambdaLoopStateProcessor` deve ir para `main.py` (ou acontecer no próprio `__init__` dele via auto-subscrição no Bus).
