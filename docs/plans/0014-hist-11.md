# História 11 — Migração UI: VeCalibrationScreen e VeWriteController para bus

**ID:** 0014  
**Área:** UI / VeCalibration Migration  
**Fase:** 5

---

## Contexto

`VeCalibrationScreen` e `VeWriteController` ainda chamam diretamente a ECU connection (`get_ecu_connection().send_command()`). A arquitetura alvo exige que toda comunicação com a ECU passe pelo bus via `EcuCommandRequestedEvent`.

Adicionalmente, `VeCalibrationScreen` se inscreve no `vehicle_state.emitter` no `__init__`, mas na arquitetura alvo o emitter foi removido (História 10) e a inscrição deve usar `event_bus` em `on_activated()`.

---

## História de Usuário

Como desenvolvedor, quero que VeCalibrationScreen e VeWriteController se comuniquem com a ECU exclusivamente via EventBus, para que o acoplamento direto a `get_ecu_connection()` seja eliminado e o padrão de comunicação seja uniforme em toda a aplicação.

---

## Requisitos Funcionais

- `VeCalibrationScreen.keyPressEvent` para teclas O e P deve publicar `EcuCommandRequestedEvent` no bus ao invés de chamar `get_ecu_connection().send_command()`.
- `VeCalibrationScreen.__init__` não deve mais conectar `vehicle_state.emitter`.
- `VeCalibrationScreen.on_activated()` deve se inscrever em `AppEventType.VEHICLE_STATE_CHANGED` via `self._subscribe()`.
- `VeCalibrationScreen.on_deactivated()` desinscreve automaticamente via `super().on_deactivated()` (comportamento já existente na base Screen).
- `VeWriteController._send_pending_rows()` deve publicar `EcuCommandRequestedEvent` para cada linha VE ao invés de `get_ecu_connection().send_command()`.
- Nenhuma das duas classes deve importar `get_ecu_connection` após a migração.

---

## Requisitos Não-Funcionais

- O comportamento funcional não muda — os comandos chegam à ECU pelo mesmo caminho, apenas passando pelo bus como intermediário.
- `VeCalibrationScreen` deve assinar `VEHICLE_STATE_CHANGED` apenas quando ativa (on_activated), não permanentemente.

**Atualizar `_on_vehicle_state_event` para receber `VehicleStateChangedEvent` (não mais `VehicleStateChangeEvent`):**

Verificar se há diferença entre `VehicleStateChangeEvent` (de `app/state/event.py`) e `VehicleStateChangedEvent` (de `app/event/app_events.py`). Ambos usam `EventType` de `app/state/event.py`. O callback recebe o mesmo tipo de objeto — verificar se a assinatura do método precisa de ajuste.

> **Nota:** `_on_vehicle_state_event` em `VeCalibrationScreen` recebe atualmente `VehicleStateChangeEvent` (de `app/state/event.py`). Após a migração, receberá `VehicleStateChangedEvent` (de `app/event/app_events.py`). Ambos têm `type_` (que é `EventType`) e `args`. Verificar se os campos são compatíveis.

**Remover import:**
```python

```

**Adicionar imports:**
```python

from app.event.app_events import EcuCommandRequestedEvent
```

**Alterar `_send_pending_rows()`:**
```python
def _send_pending_rows(self):
    pending = ve_map_state.get_pending_rows()
    if not pending:
        return
    for row in pending:
        values = ve_map_state.get_row_raw_values(row)
        cmd = EcuCommand[f"VE_ROW_{row + 1}"]
        ve_map_state.mark_row_sent(row)
        event_bus.publish(EcuCommandRequestedEvent(command=cmd, args=values))
    self._player.stop()
    self._player.play()
```
