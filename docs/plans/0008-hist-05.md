# HIST-05: Refatorar SignalProcessor para Processar ECU_MESS_FRAME por Frame

## Contexto

`SignalProcessor` atualmente recebe uma string combinada `"#D01;...;#D02;..."` via conexão direta `ecu_connection.emitter → signal_processor.process_line` em `main.py`. Ele filtra apenas linhas que começam com `#D01` e parseia todos os sinais de uma vez usando índices absolutos na string combinada. Com a nova arquitetura, cada frame chega separado via `ECU_MESS_FRAME`. O SignalProcessor deve se inscrever no Bus e processar frames individualmente, acumulando D01 e D02 antes de calcular os sinais dependentes dos dois frames.

## História de Usuário

Como sistema, quero que o SignalProcessor se inscreva em `ECU_MESS_FRAME` no Bus e acumule dados de D01 e D02 antes de emitir `SIGNALS_RECEIVED`, para que o pipeline de dados seja desacoplado da camada de transporte.

## Requisitos Funcionais

- RF01: `SignalProcessor` se inscreve em `AppEventType.ECU_MESS_FRAME` no EventBus na inicialização.
- RF02: Ao receber `EcuMessFrameEvent(frame_id="D01", raw_line=...)`, parsear os sinais pertencentes ao frame D01 (aqueles com `index` no range D01) e armazenar em `_partial_data`.
- RF03: Ao receber `EcuMessFrameEvent(frame_id="D02", raw_line=...)`, parsear os sinais pertencentes ao frame D02 e mesclar com `_partial_data`.
- RF04: Após mesclar D01 e D02, computar os sinais `calculated: True` (que dependem de ambos os frames) e adicionar ao dict.
- RF05: Publicar `SignalsReceivedEvent(data=parsed_data)` no Bus com o dict completo (D01 + D02 + calculados).
- RF06: Remover a conexão direta `ecu_connection.emitter → signal_processor.process_line` do `main.py` (feito em HIST-10).
- RF07: O método `process_line()` pode ser mantido como método interno ou removido — não deve ser chamado externamente após esta história.
- RF08: O `emitter` legacy (`Signal(dict)` em `SignalProcessor`) deve ser mantido por retrocompatibilidade temporária até HIST-09 migrar `LambdaLoopStateProcessor`.

## Requisitos Não Funcionais

- RNF01: Se D01 chegar sem D02 subsequente (frame perdido), o buffer `_partial_data` deve ser descartado quando o próximo D01 chegar (substituído pelo novo frame D01).
- RNF02: Sinais calculados (`POWER`, `TORQUE`, `VE_LAMBDA`) só devem ser computados quando ambos os frames estiverem disponíveis — não emitir parcialmente.
- RNF03: Thread safety: o callback do Bus é chamado na main thread (via QueuedConnection do pyqtSignal). Nenhum lock adicional necessário.

### Estratégia de indexação

Como a `EcuSession` emite D01 e D02 como linhas separadas (sem combinação), os índices absolutos no `Signal` enum não funcionam diretamente. Duas opções:

**Opção A (menos invasiva)**: O SignalProcessor mantém internamente a lógica de recombinação. Ao receber D01, guarda a string; ao receber D02, concatena `d01 + ";" + d02` e chama `process_combined()` — equivalente ao comportamento atual mas desacoplado da conexão.

**Opção B (mais correta)**: Adicionar campo `"frame"` e `"frame_index"` ao `Signal` enum para indicar qual frame pertence e o índice relativo dentro do frame. O SignalProcessor aplica o offset correto por frame.

**Decisão de implementação**: Usar Opção A para esta história (menos impacto no Signal enum, que é a "fonte da verdade" do projeto). O campo `"frame"` pode ser adicionado separadamente se necessário no futuro.

### Implementação com Opção A

```python
class SignalProcessor(QObject):
    emitter = Signal(dict)  # legado, manter temporariamente

    def __init__(self):
        super().__init__()
        self._d01_buffer: str | None = None
        from app.event.bus import event_bus
        from app.event.app_events import AppEventType
        event_bus.subscribe(AppEventType.ECU_MESS_FRAME, self._on_mess_frame)

    def _on_mess_frame(self, event: EcuMessFrameEvent):
        if event.frame_id == "D01":
            self._d01_buffer = event.raw_line
        elif event.frame_id == "D02" and self._d01_buffer is not None:
            combined = f"{self._d01_buffer};{event.raw_line}"
            self._d01_buffer = None
            self._process_combined(combined)
        # D03 ou D02 sem D01 anterior: ignorar

    def _process_combined(self, line: str):
        # Lógica atual de process_line(), adaptada para linha combinada
        parts = line.split(";")
        parsed_data = {}
        for signal in SignalEnum:
            try:
                if signal.value.get("calculated", False):
                    try:
                        raw = signal.value["value"](parsed_data)
                        value = raw
                    except:
                        raw = -1
                        value = -1
                else:
                    idx = signal.value["index"]
                    if idx >= len(parts):
                        continue
                    raw = parts[idx]
                    value = signal.value["converter"](raw)
                parsed_data[signal] = ParsedSignal(signal, raw, value)
            except Exception:
                logger.exception("Erro ao processar sinal %s", signal)
        self.emitter.emit(parsed_data)  # legado
        event_bus.publish(SignalsReceivedEvent(data=parsed_data))
```
