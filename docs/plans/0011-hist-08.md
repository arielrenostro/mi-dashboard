# HIST-08: Adaptar VeCalibrationScreen e VeWriteController ao EventBus e EcuSession

## Contexto

`VeCalibrationScreen` viola dois princípios da nova arquitetura:
1. Conecta-se diretamente a `vehicle_state.emitter` para receber mudanças de mapa/breakpoints, em vez de usar o EventBus.
2. Chama `get_ecu_connection().send_command()` diretamente nas teclas O (open loop) e P (close loop), em vez de publicar evento no Bus ou chamar método da Session.

`VeWriteController` também chama `get_ecu_connection().send_command()` diretamente para escrever linhas VE.

## História de Usuário

Como desenvolvedor, quero que `VeCalibrationScreen` se inscreva em `VEHICLE_STATE_CHANGED` via EventBus para receber atualizações de mapa, e que as ações de lambda loop e escrita VE passem pela Session ou pelo Bus, para eliminar o acoplamento direto com a camada de comunicação.

## Requisitos Funcionais

- RF01: `VeCalibrationScreen` deve se inscrever em `AppEventType.VEHICLE_STATE_CHANGED` via `_subscribe()` no `on_activated()` (e desinscrever em `on_deactivated()` via o mecanismo base da `Screen`).
- RF02: Remover `vehicle_state.emitter.connect(self._on_vehicle_state_event)` do `__init__()`.
- RF03: `_on_vehicle_state_event` deve passar a receber `VehicleStateChangedEvent` (dataclass do Bus) em vez de `VehicleStateChangeEvent` (dataclass interna do vehicle_state). O `change_type` continua sendo `EventType` da `app/state/event.py`.
- RF04: Na tecla O (open loop): publicar `EcuCommandRequestedEvent(command=EcuCommand.LAMBDA_LOOP_OPEN)` no Bus OU chamar `get_ecu_session().open_loop()` diretamente. Preferir chamar o método nomeado da Session.
- RF05: Na tecla P (close loop): equivalente ao RF04, mas `close_loop()`.
- RF06: `VeWriteController._send_pending_rows()` deve chamar `get_ecu_session().send_command(cmd, values)` em vez de `get_ecu_connection().send_command(cmd, values)` — funcionalmente equivalente após o registry expor `get_ecu_session()`.
- RF07: `VeCalibrationScreen` deve se inscrever em `AppEventType.SIGNALS_RECEIVED` via Bus no `on_activated()` para atualizar a top bar, em vez de usar apenas o timer de 100ms.

## Requisitos Não Funcionais

- RNF01: A subscrição em `VEHICLE_STATE_CHANGED` deve acontecer em `on_activated()` (não no `__init__()`), seguindo o padrão da `Screen` base.
- RNF02: `on_deactivated()` já chama `super().on_deactivated()` que desinscreve todos os tokens — nenhuma mudança necessária neste método além de parar o timer.
- RNF03: A chamada direta a `get_ecu_session().open_loop()` é aceitável (Screen chamando Session diretamente) pois é mais simples que o fluxo REQUESTED→Session. O `ECU_COMMAND_REQUESTED` pode continuar existindo para o `LambdaToggle`, mas `VeCalibrationScreen` usa método direto.

### Mudanças em `_on_vehicle_state_event`

```python
def _on_vehicle_state_event(self, event: VehicleStateChangedEvent):
    # VehicleStateChangedEvent.change_type é EventType de app/state/event.py
    # VehicleStateChangedEvent.args é tuple
    if event.change_type == EventType.MAP_BREAKPOINTS:
        ve_map_state.load_breakpoints_map(event.args[0])
        self.refresh_axes()
    elif event.change_type == EventType.RPM_BREAKPOINTS:
        ve_map_state.load_breakpoints_rpm(event.args[0])
        self.refresh_axes()
    elif event.change_type == EventType.FUEL_MAP:
        ve_map_state.load_row(event.args[0], event.args[1])
        self.update_row(event.args[0])
```

Lógica idêntica à atual; só muda o tipo do evento recebido.
